# HakiSend Publisher v0.1.3 — test checklist

## Scope
This is a test-only draft on an isolated Obsidian vault. It does not add bidirectional content sync, mobile device vault sync, email campaigns, free excerpts or calendar yet. Do not use Publish Now or Schedule against production until reviewed.

## Verify new-post folder chooser
1. Open an existing note in `KIEN OS/Business`, even if `Research` is the currently selected folder in the sidebar.
2. Run `HakiSend: New Post`. Its initial folder follows the currently open note.
3. Click **Choose folder…**, search `KIEN OS/Business/Research`, choose the nested folder.
4. Assert the form shows that exact folder, Site `KIÊN OS`, and Category `BUSINESS` as the suggested value inherited from its parent mapping.
5. Create title `Research Draft 01` and inspect that file was created under `KIEN OS/Business/Research` with `site_uid`, `category_uid`, `category`, `external_id`, and `status: draft`.
6. Run **Save Changes** only; verify exactly one server Post under KIÊN OS / BUSINESS. Save again and verify the same Post UID is updated.
7. Reopen New Post; select `KIENPARENTING/Parenting Mindset` and confirm its site changes to KIÊN PARENTING and its category choices belong only to that Site.
8. Select a folder with no Category route and a name that does not match a Category; it must demand a deliberate Category choice, not silently pick the first.
9. Test wrong Site / deleted folder / inaccessible Category; do not create a draft. The modal must report an error and leave the earlier file untouched.
10. Verify the existing mappings and connection survive upgrading just `main.js`, `manifest.json`, `styles.css` (do not overwrite `data.json`).

## Distinction to keep
- Folder Site mapping: parent prefix, overridden by explicit note `site_uid`.
- Folder Category mapping: longest inherited prefix, scoped to resolved Site.
- New Post saves a pinned Site UID and Category UID to prevent later file moves silently migrating posts.
- No server write occurs from **Create draft** alone. Only **Save Changes** sends the Post.

## Rollback
Preserve a local ZIP/tar backup of the currently working plugin files before updating. Restore the old plugin files and restart Obsidian. Preserve the Vault and `data.json` across rollback.
